# UV Texel Equalizer

Аддон версии **1.1.0** для Blender 4.3+ / 5.x. Проверен в Blender 5.0.0.
Обрабатывает **все UV-острова одного активного меша**, включая скрытые и невыделенные грани.
Запуск файла только добавляет интерфейс — развёртка сама не меняется.

## Запуск

1. В Blender откройте **Scripting → Text Editor → Open** и выберите `uv_texel_equalizer.py`.
2. Нажмите **Run Script** (`Alt+P`, когда указатель находится в Text Editor).
3. Выберите нужный меш. В **UV Editor** откройте боковую панель клавишей `N`, вкладка **Texel**.
4. Задайте реальную ширину и высоту текстуры. Пустое поле «UV-слой» означает активный слой.
5. Нажмите **«Проверить плотность и растяжения»**.
6. При необходимости нажмите **«Выделить растянутые грани»**. Эта кнопка специально включает Edit Mode и меняет выделение.
7. Если проверка не выявила проблем, нажмите **«Выровнять тексель всех островов»**. Отмена изменения — `Ctrl+Z`.

Можно также установить ZIP как обычный legacy add-on через **Preferences → Add-ons → Install from Disk**.
Текстовый отчёт `Texel_Equalizer_Report.json` появляется внутри текущего `.blend`, в списке Text Editor. В нём есть плотность каждого острова, среднее, отклонения и номера проблемных граней/островов. Номера граней в отчёте начинаются с 1.
Сам `.blend` скрипт автоматически не сохраняет.

## Ориентация островов — новое в 1.1

В панели **Texel → Ориентация UV относительно модели** появились две кнопки:

1. **«Проверить ориентацию островов»** — находит зеркальные, повёрнутые и неоднозначные острова, без изменения UV.
2. **«Исправить зеркальность и верх UV»** — отражает зеркальные острова и поворачивает их так, чтобы верх модели смотрел вверх по оси V развёртки. Исправляются как переворот на 180°, так и повороты на 90° и произвольные углы.

По умолчанию верх модели — **мировая Z**. Если поверхность горизонтальная и Z не задаёт на ней направление, используется запасная **мировая Y**. Обе оси можно выбрать в панели; они должны различаться. Поворот объекта и знак его масштаба учитываются. Для изогнутых вертикальных окон направление верха вычисляется по треугольникам всего острова.

Зеркальность определяется по ориентации UV-треугольников относительно порядка вершин поверхности с учётом отрицательного масштаба объекта. Это развитие проверки `mirrored_uv_checker.py` предоставленного ATRIUM AGR; вместо изменения отдельных полигонов преобразуется остров целиком. Геометрические нормали и порядок вершин модели должны быть согласованы: аддон не угадывает, где находится наружная сторона меша, и не исправляет его нормали.

Отражение выполняется по U относительно центра острова, затем применяется необходимый поворот. Для прямоугольных текстур операции выполняются **в пиксельной метрике**: так сохраняется форма изображения на модели. В UV-координатах прямоугольной текстуры это может выглядеть иначе, чем обычный поворот редактора UV, но не добавляет растяжение текстуры.

Исправление ориентации **не выравнивает плотность**: оно сохраняет прежний тексель каждого острова. Выравнивание плотности и исправление ориентации — две отдельные операции с отдельной отменой `Ctrl+Z`. Обычно удобно сначала исправить ориентацию, затем выровнять плотность.

Защиты закреплённых UV, общего Mesh Data, новых пересечений и точности float32 действуют и при исправлении ориентации. Перед записью проверяется плотность и форма каждого треугольника. Если проблема найдена, эта операция отменяется целиком. Новая упаковка не выполняется; после поворота остров может выйти за пределы 0–1, что отмечается в отчёте.

**Неоднозначные острова не поворачиваются автоматически.** Например, на одной связной развёртке замкнутой сложной детали «верх» разных граней может требовать противоположных поворотов. Аддон выдаёт номера таких островов и ничего не меняет. Смешанная зеркальность внутри одного острова также требует ручной проверки UV/нормалей. Подходящий выбор осей либо дополнительный UV-разрез может устранить неоднозначность; деформация острова для её устранения не применяется.

Допуск ориентации по умолчанию — **1°**, настраивается отдельно от допуска тексельной плотности. Отчёт содержит использованную мировую ось, необходимый поворот, зеркальность, согласованность направлений и результат проверки после исправления.

## Как считается тексель

Для острова: **D = √(площадь UV в пикселях / площадь поверхности в м²)**, единицы — px/m.
Площадь считается по реальной триангуляции Blender, с учётом масштаба объекта и `Scene → Units → Unit Scale`. Перенос объекта не влияет на результат. Модификаторы не вычисляются: проверяется редактируемая геометрия меша. Для плотности конечной поверхности меняющие геометрию модификаторы должны быть предварительно применены к отдельной копии объекта.

По умолчанию среднее — **квадратичное, взвешенное по площади поверхности**:

`Dсреднее = √(Σ площади UV в пикселях / Σ площади поверхности в м²)`.

Так после выравнивания сохраняется суммарная площадь UV. Если требуется буквальное арифметическое среднее плотностей всех островов, выберите **«Арифметическое по островам»**. Также есть арифметическое среднее с весом по площади 3D.

Каждый остров масштабируется с коэффициентом `Dсреднее / Dострова`, **одинаковым по U и V**, относительно центра своего UV bounding box. Его ориентация, форма и внутренние пропорции сохраняются. Материалы, геометрия, остальные UV-слои, разрезы, выделение и скрытие не меняются при проверке/выравнивании. В Object Mode общий Mesh Data по умолчанию отделяется, чтобы не менять другие объекты, использующие те же данные.

Математически плотности становятся равными. Координаты UV Blender хранятся как float32, поэтому абсолютное побитовое равенство произвольных плотностей недостижимо. Скрипт заранее проверяет результат именно после округления в float32. Допуск по умолчанию — **0,00001 относительной ошибки, то есть 0,001%**. При невозможности его достигнуть скрипт не записывает изменения.

## Защита от растяжений

Использован принцип `Find Stretched Faces` из предоставленного `ATRIUM_AGR_v2_0.zip`, модуль `angle_distortion_checker.py`: сравнение углов геометрии и UV.
Исходный оператор аддона не вызывается, поскольку он принудительно меняет режим/выделение, проверяет только треугольники и четырёхугольники, жёстко использует слой `UVMap` и локальные координаты.

Дополнительно скрипт проверяет:

- углы всех полигонов и их треугольников в реальном масштабе объекта;
- анизотропию каждого треугольника по отношению сингулярных чисел UV-преобразования;
- разброс локальной плотности внутри острова;
- схлопнутые UV, вырожденную геометрию, NaN/Infinity и смену ориентации UV;
- сохранение формы после округления новых UV до точности Blender;
- сохранение состава UV-островов и отсутствие новых пересечений между ними.

Проверка анизотропии обнаруживает, например, квадрат, растянутый в прямоугольник: у его углов всё ещё 90°, поэтому одной проверки углов недостаточно.

**Уже существующие растяжения равномерным масштабированием устранить невозможно.** В строгом режиме, включённом по умолчанию, обнаруженные исходные искажения блокируют выравнивание. Порог исходного растяжения/разброса плотности по умолчанию — 1%, угла — 1°. При отключении строгого режима средняя плотность островов выровняется, но исходные искажения останутся. Проверка сохранения формы нового результата остаётся включённой всегда.

## Размещение островов и ограничения

- Упаковка и повторный unwrap не выполняются: они изменили бы расположение UV. Рост островов может потребовать свободного места. Защита от **новых** пересечений включена по умолчанию; при конфликте всё выравнивание отменяется, и нужно сначала раздвинуть острова. Уже существующие перекрытия не устраняются.
- UDIM и координаты вне 0–1 разрешены. Острова не возвращаются автоматически в исходный тайл. Выход за 0–1 отмечается в отчёте. Очень маленькие острова на больших координатах могут упереться в точность float32; тогда изменений не будет.
- Введённое разрешение относится **ко всей проверяемой развёртке**. Для материалов/UDIM-тайлов с разными разрешениями одного общего значения недостаточно: сначала приведите их к общей пиксельной метрике. По шейдерным нодам скрипт разрешение не угадывает.
- Закреплённые UV по умолчанию защищены. Если равномерное масштабирование переместит Pin, операция отменяется. Это можно явно отключить в панели.
- Любая ошибка до записи отменяет операцию целиком. При ошибке записи восстанавливаются предыдущие UV.
- При намеренно включённом изменении общего Mesh Data вместо отделения копии UV изменятся у всех объектов, использующих эти данные.
- После изменения числа полигонов в меше нужно заново выполнять проверку: номера граней в старом отчёте могут стать неактуальными.

## Вызов из другого скрипта

```python
import importlib.util
spec = importlib.util.spec_from_file_location('texel_eq', r'C:\путь\uv_texel_equalizer.py')
texel_eq = importlib.util.module_from_spec(spec)
spec.loader.exec_module(texel_eq)

# Только отчёт, без изменения UV:
report = texel_eq.equalize(apply=False, width=2048, height=2048)

# Все проверки и выравнивание активного меша:
report = texel_eq.equalize(apply=True, width=2048, height=2048,
                         average='AREA_RMS', strict=True)

# Проверка и исправление ориентации (мировая Z вверх, для пола — Y):
orientation_report = texel_eq.orient(apply=False, axis='Z', fallback_axis='Y')
orientation_report = texel_eq.orient(apply=True, axis='Z', fallback_axis='Y')
```

Функции не требуют регистрации панели и не зависят от установленного ATRIUM AGR.
