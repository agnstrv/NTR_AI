# Атлас секций по исходной геометрии

Автор опыта и адаптации: nagornov-artem; исходный workflow: Рома.
Статус: prototype. Карточка AI-20261002-04: https://trello.com/c/OgAc8RDu.
Постановка и проверки: ../../jobs/ai-20261002-04-window-atlas/.

Скрипт для Blender 5.0: разделяет вертикальные копланарные поверхности по импостам, сопоставляет категории source ближайшими двусторонними лучами и помещает UV в левую половину 2048². Это реализация конкретного производственного опыта, не принятый универсальный генератор.

## Запуск

Запускайте Blender с `--background --factory-startup INPUT.blend --python build-window-atlas.py -- --config ABSOLUTE_CONFIG.json`. Конфигурация и output должны находиться вне Git-репозитория. Исходник не перезаписывается; output blend обязан отличаться от входного.

JSON-параметры:
- `output`: абсолютная папка результата;
- `targets`: имена целевых mesh-объектов;
- `source_collection`: имя коллекции исходника;
- `source_ids`: словарь строковых ID в квадратных скобках имени → категория 1 (160/160/160), 2 (белый), 3 (32/32/32); остальные красные;
- `image_name`, `blend_name`: имена итоговых файлов;
- `group_tolerance`: допуск границ в пикселях (в данном опыте 2).

Для параллельного чтения допустимы отдельные workers: добавить `--raster-worker INDEX COUNT`. Они читают один исходник, но записывают непересекающиеся номера cache-секций; сцену не сохраняют. После завершения всех workers обычный запуск собирает атлас. Не запускать два сборщика одновременно в одной output-папке.

## Ограничения

- Метры, scale_length=1 проверены в текущем опыте; допуски и плотности не являются нормой NTR.
- У source не должно быть геометрически значимых модификаторов/instances: текущая реализация использует mesh data. Это проверено на текущем входе.
- Растеризация 64 пробы на единицу; конечный масштаб выбирается по вместимости. Тёмные тонкие элементы сохраняются консервативным pooling и могут утолщаться. Проверка исходника и PNG обязательна.
- Совпадение проверяется по порядку границ, числу компонент и двустороннему расстоянию. Это гарантия на дискретных изображениях, не ниже разрешения пробы.
- Неплоские исходные грани не режутся. Для текстуры используется плоская проекция; это отдельное ограничение для проверки.
- Неопределённые пробы красные, учёт отдельно от попаданий в другие объекты. Между цветами нет интерполяции; текстурный узел Closest.
- Cache зависит от SHA256 входного blend, конфигурации, плотности, версии sampling и geometry helper. При изменении алгоритма sampling увеличивать sampling_version.
- JSON с геометрией, cache, PNG, blend и previews — клиентские материалы. Не публиковать их в Git.

Синтетические проверки упаковки и группировки находятся в ../../tests/window-atlas/. Они не заменяют проверку реальной модели и приёмку человеком.

## Режим ограниченного числа шаблонов

Для пользовательского ограничения до 20 типов поддерживается внешний `template_plan`: JSON с `templates` (последовательные id, png, members, representative_section) и полным списком `assignments` (section, template). PNG шаблонов должны иметь дискретную палитру, RGB8, filter 0. План и PNG — клиентские материалы вне Git. Это режим явно согласованного упрощения; прежний допуск плотной группировки в нём не заявляется.

`cache_root` позволяет читать неизменяемый cache исходной плотной сборки, сохраняя новую копию в другой output-папке. Обязательны полный независимый аудит проекции и визуальная проверка упрощений. Пустая или неполная привязка секций отвергается.

`black_edge_traces=true` — согласованная для данного опыта замена коротких красных отрезков возле края на чистый чёрный. Предел — 6% длины проверяемой оси (минимум 2 пикселя), отрезок должен пересекать такую же краевую зону. Внутренние длинные полосы и большие красные поля защищены независимым аудитом. В template-mode изображения не уменьшаются: сохраняются исходные пиксели представителей, затем добавляется padding.
