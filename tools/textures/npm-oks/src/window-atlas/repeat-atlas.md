# Атлас повторяемых оконных секций

Автор адаптации: nagornov-artem. Статус: прототип на основе сценария НПМ ОКС.

`build-repeat-atlas.py` собирает RGB PNG 2048 × 2048 из измеренных шаблонов окон, однотонных плашек и опциональных масок балконов. Каждый повтор окна использует UV-прямоугольник одного шаблона. Подготовку размеров, привязку к граням, развёртку балконов по длине и подключение карт выполняет вызывающий процесс.

## Запуск

Нужен Python 3.10+, Pillow 9.1+ и существующий `atlas_packing.py` рядом со скриптом. Упаковщик резервирует поля без поворота тайлов. Скрипт выбирает максимальную целочисленную плотность из заданного диапазона, которую смог упаковать.

```sh
python -m pip install "Pillow>=9.1"
python build-repeat-atlas.py --config repeat-atlas-example.json --output atlas-output --pbr
```

Результат включает цвет `_d_1.png`, карту видимости `_o_1.png` при наличии балконных масок и JSON раскладки. Флаг `--pbr` добавляет бинарные `_m_1.png` и `_r_1.png`. Стекло получает Metallic 255 и Roughness 0, остальные пиксели получают Metallic 0 и Roughness 255. Во всех оконных и однотонных зонах видимость равна 255. Готовые файлы с теми же именами защищены от перезаписи.

## План тайлов

См. [синтетический пример](repeat-atlas-example.json).

| Поле | Содержание |
| --- | --- |
| `prefix` | Основа имён файлов. Латиница, цифры, дефис и подчёркивание. По умолчанию `atlas`. |
| `padding_px` | Поле вокруг каждого тайла. По умолчанию 16 px. Краевые пиксели продолжаются в поле синхронно по всем картам. |
| `density_px_per_m` | Целочисленные `minimum` и `maximum`. По умолчанию 40…128 px/м. |
| `background_rgb` | sRGB фона цветовой карты. По умолчанию `[255, 255, 255]`. |
| `windows` | Уникальные шаблоны с `id`, `width_m`, `height_m`, `frame_rgb` и `panes`. |
| `swatches` | Однотонные участки с `id`, `size_px: [w, h]`, `rgb`. |
| `balconies` | Участки с `id`, `size_px`, `rgb` и рядами `bars: [[u0, u1], ...]` либо `mask_png`. |

Все RGB задаются целыми числами от 0 до 255. У панели окна задать `bounds: [u0, v0, u1, v1]`, `rgb` и `kind` со значением `glass` или `opaque`. По умолчанию категория `glass`. Координаты панели нормированы в границах тайла. Ноль по V соответствует низу окна. Панели растрируются по центрам пикселей с резкой границей. Категория панели определяет свойства материала даже при одинаковых RGB стекла и глухой панели.

Балконные интервалы идут слева направо по всей ширине UV. PNG маска указывается относительно JSON и имеет точный размер содержимого без полей. Подходят бинарный канал серого, одинаковые каналы RGB или явный альфа-канал RGBA/LA. Белый пиксель соответствует видимой части ограждения. В цветовой карте фон прозрачных просветов равен цвету ограждения.

## Использование результата

В JSON поля `content_xywh` и `padded_xywh` отсчитываются сверху слева. Поля `uv_min` и `uv_max` задают нормированный прямоугольник содержимого с началом снизу слева. Для каждого повторения шаблона переносить локальные UV линейно в этот прямоугольник. Для `_d_1` использовать sRGB, для остальных карт выбрать Non-Color. Проверить отображение тонких импостов и просветов на модели с ближайшей фильтрацией.

Конкретные цвета и границы извлекать из согласованных материалов и исходной геометрии объекта. Параметры плотности и полей относятся к генератору. Размещение UV и проверка результата на модели выполняются отдельно. Клиентские планы, маски, текстуры и сцены хранить в рабочей папке проекта вне Git.
