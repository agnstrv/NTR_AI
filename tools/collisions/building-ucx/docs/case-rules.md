# Правила, утверждённые пользователем для производственного кейса

Источник: диалог по зданию 16–17.10.2026, четыре пары изображений
«модель / желаемая коллизия» и последующие уточнения. Изображения клиента не публикуются.
Эти численные нормы не являются стандартом всех проектов NTR.

1. Максимальное отклонение от геометрии — 0,25 м. Это верхний предел упрощения,
   а не целевая толщина или обязательный отступ. Делать аккуратнее, когда возможно.
2. Не более 999 отдельных выпуклых UCX-объектов на результат. Проверять бюджет
   до полного запуска и после добавления деталей, а не только в конце.
3. Предпочитать коробчатые объёмы; треугольные формы — когда другой вариант не подходит.
   Поворачивать объём вдоль стены/ограды: один прямой участок — один объём, если возможно.
4. Обвести основную форму здания, считая рамы и стекло продолжением стены.
   Закрывать фасад по стеклу; углубления и импосты не моделировать. Ранее предложенный
   вариант со сквозными оконными проёмами отменён пользователем.
5. Замыкать каждую часть. Разделять на изгибах, чтобы отдельные UCX оставались выпуклыми.
   Дворы, проходы и пустоты под консолями сохранять. Днище разрешено по нижнему контуру стен.
6. Между соседними частями — 2 мм. Разрез создаёт два закрытых объёма, не две открытые оболочки.
7. Ламели каждого навеса объединять в сплошное покрытие по общей форме навеса.
   Овальная выпуклая плита допустима — это показано в примере пользователя.
8. Изначальный порог перил был «толще 5 см». Последующее явное уточнение:
   делать общий барьер всей секции, в том числе для поручней около 4 см.
   Тонким перилам нужна тонкая коллизия фактической толщины; не раздувать до 25 см.
9. Лестничный марш — один закрытый объём со скатом, поверхность которого проходит
   по передним верхним углам ступеней. При нескольких направлениях маршей требуется
   отдельное решение, а не вогнутый общий UCX.
10. На неоднозначных участках показывать конкретный узел пользователю и согласовывать.
    Работать в фоне, в копии исходника; предоставлять промежуточный файл по запросу.

Примеры задают уровень упрощения: стены без рам и мелкой сетки; навес одной общей
плитой с опорами; ограда сплошными тонкими секциями; близкие фасадные пояса можно
укрупнять вертикально, если сохраняется допуск. Большие промежутки автоматически
заполнять нельзя.

## Уточнения 28–29.10.2026

Источник: прямые указания пользователя в продолжении диалога. Пользователь явно
подтвердил применение прежнего набора численных параметров ко второму тесту
(case-002-collision-test); это не распространение норм на все проекты NTR.

- 999 — жёсткий потолок, не целевое число. Всегда стремиться минимизировать число
  объёмов, объединяя совместимые участки в пределах согласованного допуска.
- Все ламели, включая вертикальные экраны, закрывать сплошным объёмом каждой
  непрерывной секции. Не строить отдельный UCX на каждый ламель. Делить только
  по общей форме для выпуклости, сохраняя архитектурные отверстия и проходы.
- Небольшие остаточные микрообъёмы после разрезов, подобные показанному пользователем
  фрагменту на стене, удалять. Численный порог размера не установлен; не придумывать
  универсальный отсев и не удалять функциональные тонкие перила или исходную модель.
- Перед передачей сохранять объекты коллизии с display_type=SOLID и режимом
  просмотра Solid. Проверять настройку после повторного открытия файла.
- Каждые 30 минут активной работы передавать сохранённый промежуточный blend,
  краткий статус и вопросы по действительно спорным участкам. Это порядок активной
  работы, а не разрешение запускать задачи по расписанию без запроса.

### Лимит треугольников второго теста

По предоставленному скриншоту: если исходная модель содержит менее 50 000
треугольников, лимит коллизии — 15 000; для остальных — ceil(N * 0.05),
с округлением вверх. Для второго теста N=580 578, лимит=29 029.
Норма применяется вместе с лимитом частей; малое число треугольников не отменяет
проверку формы. Источник — скриншот пользователя, не универсальный стандарт NTR.
