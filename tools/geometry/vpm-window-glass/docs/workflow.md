# Последовательность, архитектура и ограничения

Работать только на копии, сохранить ручную резервную версию. Это исторический набор case-specific алгоритмов без транзакционного отката всей цепочки; отдельный Python-вызов не гарантирует Ctrl+Z. Возврат — заново открыть копию до этапа. Прямой Run Script вызывает `__main__` и может изменять сцену.

## Наружные плейны

1. `window_planes.create_window_planes(source_name=...)`: группирует рамы, ищет XY-траектории, строит плоскости, сохраняет изгибы. Единицы — метры, Unit Scale = 1. Плейны помечаются `window_plane`; исходные рамы не заменяются. `main()` по умолчанию также применяет следующий этап; существующие плейны используются повторно, `recreate=True` создаёт новую коллекцию.
2. `window_plane_adjust.adjust_window_planes(planes, source_name=..., expansion=.10)` смещает к наружной поверхности и расширяет на 10 см. Сохраняет базовые координаты, повтор не накапливает смещение. В том же модуле `fix_window_plane_normals` направляет нормали по смещению.
3. `window_plane_cutouts.cut_window_planes(planes, source_name=...)` вырезает внутренние пустоты, включая области между импостами. **Это плейны контура рам, а не финальная сплошная поверхность стекла.** Внешний запас сохраняется. `window_plane_cutouts` используется также как свойство результата.
4. `window_plane_cleanup.cleanup_window_planes(planes)` и `repair_window_junctions(planes)` очищают сетку/Т-стыки. Не гарантировать отсутствие дефектов без проверки результата.
5. `window_quad_retopology` содержит основной и legacy-вариант ретопологии конкретного объекта `Окно_Plane_001`, использует `WindowFrameSource`. Это отдельная историческая доводка, не обязательный массовый этап. Внутренний legacy-алгоритм не удалён; универсальность не установлена.

## Серединное стекло

Исходный `Plane` — рамы после применения Solidify. Алгоритм **предполагает попарно упорядоченные слои вершин**, делит массив пополам и вычисляет середину пар; произвольный Solidify mesh этому контракту не обязательно соответствует. Пользователь менял сцену вручную между этапами. Составление графа профилей зависит от вертикали Z и горизонтальной траектории XY.

Историческая подготовка: сохранить `outputs/Windows_Infill_Before.blend` во внешнем scratch-корне; `src/work/analyze_infill.py` извлекает `infill_geometry.json`; `infill_loops.py` строит loops; `prepare_infill.py` — profiles, используя функцию profile из `outputs/window_quad_retopology.py`. Все скрипты используют layout `src/{outputs,work}`. Подготовительные scripts запускают действия на верхнем уровне: не импортировать в живую сессию без просмотра. **`infill_loops.py` содержит специальные пары component ID `{163,164}` и `{179,194}` — это исправления одного кейса, не общее правило.** Геометрические JSON намеренно не опубликованы. Для повторения перенести набор в отдельную локальную scratch-копию и подготовить согласованные входы; не писать результаты/клиентские модели в Git checkout.

`window_infill_planes.build()` читает три подготовленных JSON, проверяет совпадение исходных вершин `Plane`, создаёт quad-заполнения отдельных проёмов в середине толщины с overlap 0,02 м. Создаёт новую коллекцию; повтор может создавать дубли. Трансформации берёт из `infill_geometry.json`. Не делает материал/готовую развёртку стекла.

## Непрерывная поверхность на окно

После ручных действий пользователя отдельные заполнения находились в объекте `Окно_Заполнение_001`. Подготовка `analyze_continuous.py` читает два исторических снимка `work/Windows_Infill_Review.blend` и `outputs/Windows_Continuous_Before.blend`, сопоставляет вершины с frame_component и строит `continuous_groups.json`; `continuous_profiles.py` создаёт `continuous_profiled.json`. Эти модели и JSON отсутствуют в Git. Полностью автоматического объединения между этапами набор не содержит.

`window_continuous_infill.build()` читает профиль, заменяет **весь Mesh Data** объекта `Окно_Заполнение_001`, сохраняет повороты/изгибы по профилю, материалы и интерполирует UV из старых треугольников. Посторонние грани, не представленные в groups, не копируются; нужны согласованные source и профиль. Нет общего теста произвольных окон, отверстий и вложенных контуров. Остальные объекты не являются целью функции. Результат — по одной связной поверхности на распознанное окно, дополнительные рёбра только по изгибам/контурным ограничениям. **Фактическое совпадение UV и нормалей обязательно проверять**, наличие интерполяции не гарантирует готовность стекла.

## Непринятые варианты и проверка стыков

Union импостов в пределах 0,05 м не устранил пользовательскую задачу; пользователь отменил изменения. Сохранён только как experimental, отдельно от цепочки стекла. Промежуточная quad-аудиторская проверка зафиксировала 3 nonmanifold и большой boundary distance; поздний отчёт по другому сохранённому результату не доказывает исправление всех метрик раннего аудита. Для применения проверять силуэт/стыки/кривизну, нормали, T-junctions, self-intersection, количество связных частей, материал и UV, а затем критерии карточки. Отступы 10 см/2 см и допуски в коде относятся к этому кейсу; нормы команды не назначаются.
