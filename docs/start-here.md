# Начать работу в NTR

Это входная страница для передачи репозитория команде.

## Первый запуск

1. Получите доступ к [репозиторию NTR_AI](https://github.com/agnstrv/NTR_AI) под своей учётной записью GitHub.
2. Если локальной копии нет, клонируйте репозиторий через GitHub Desktop или `git clone https://github.com/agnstrv/NTR_AI.git`.
3. Если копия есть, проверьте `git status` и сохраните текущие изменения в своей ветке. Затем выполните `git fetch origin`. Fetch скачивает историю, но не обновляет рабочие файлы.
4. Для новой задачи перейдите на main и обновите его: `git switch main`, затем `git pull --ff-only origin main`. При конфликте или локальных коммитах агент сначала разбирает состояние, не делает reset и не удаляет работу.
5. Откройте локальную папку репозитория как проект агента. Начните новую сессию. Попросите прочитать `AGENTS.md`, назвать актуальные правила и проверить обнаружение навыков по `process/agent-skills.md`.
6. Выберите один из двух промптов ниже. Агент создаст ветку `work/<author>/<tool>/<job-id>` до изменений. Личный slug согласуйте и используйте одинаково; он не обязан совпадать с логином GitHub.

| Ситуация | Что дать агенту |
|---|---|
| Собрать накопленные скрипты и незавершённые разработки | [Промпт №1](../prompts/01-collect-local-work.md) |
| Новая задача, продолжение или проверка чужого решения | [Промпт №2](../prompts/02-start-or-continue.md) |

Укажите своё имя, задачу Trello, разрешённые рабочие папки и ожидаемый результат. Для новой задачи модель требуется только тогда, когда она нужна для самой работы.

## Ежедневная работа

[Блок-схемы](team-workflow/README.md) показывают весь цикл. Автор сохраняет commit и делает push в ветку задачи. Проверяющий получает ветку, запускает решение у себя, фиксирует результат и решает о включении. Для merge используется PR. Доработав алгоритм коллеги, передайте изменённую версию другому человеку для проверки.

- [Памятка: fetch, ветки, worktree и команды](../process/team-quickstart.md).
- [Каталог инструментов](../tools/README.md).
- [Правила имён и файлов](../process/repository-structure.md).
- [Подключение навыков Matt](../process/agent-skills.md).

## После обновления структуры

Старые разработки перенесены в tools; [карта переноса](../process/repository-migration.md) сохраняет соответствие адресов. Если работаете в старой ветке, интегрируйте актуальный main с помощью агента, разберите конфликты переименования и продолжайте в новом пути. Не загружайте старую папку заново.

Первый запуск навыков на каждом ПК и производственные проверки прототипов выполняются участниками. Документы и исходники уже доступны для начала работы.
