# NTR — правила для агента

Общий репозиторий команды NTR (цифровые двойники: НПМ, упрощённый НПМ, ВПМ; Ground и ОКС).
Здесь лежат сценарии, тулзы и журнал работы команды с ИИ. По записям в ветках строится дашборд руководителя, поэтому каждая задача проходит один и тот же цикл.

## Команды

Скилл — это файл `.agents/skills/<имя>/SKILL.md`. Человек может написать имя словом, как `/имя` или `$имя`. Если твой интерфейс скиллы не подключил — открой файл и выполни его.

| Когда | Скилл |
|---|---|
| Новая сессия или новая задача, любое первое сообщение («привет», «пришла задача», «ntr») | `ntr` — аудит → готовые сценарии коллег → паспорт → план с приёмкой шагов |
| Контекст заполнен на 40–50%, «handover», переход в новый чат | `ntr-handover` — состояние задачи уходит на GitHub |
| Новый чат после handover, «takeover», «продолжаем» | `ntr-takeover` — подхватить с последнего состояния |
| «Сдаю», «retro», задача принята или не получилась | `ntr-retro` — время, сценарий с версией, реестр, push ветки, PR |
| Новая идея без готового сценария | `grill-me` — вопросы до ясной постановки |
| Навести порядок в Trello | `ntr-trello-sync` |

Режимы внутри задачи выбирает `ntr`: `ntr-apply` (применить готовое), `ntr-contract` (сценарий), `ntr-tool` (тулза), `ntr-discuss` (обсуждение).

## Правила

1. Первое действие в сессии — `ntr`. До подтверждённого паспорта задачи работа не начинается.
2. Исходники проекта остаются нетронутыми: работай с копиями в `<папка проекта>/AI/input`, результаты — в `AI/output`, принятое — в `AI/finish`.
3. В репозиторий идут только текст и скрипты. Клиентские модели, альбомы, текстуры, имена заказчиков и локальные пути (`C:\...`) остаются на ПК.
4. Работай в своей ветке `work/<id>/<тема>`. В `main` вливает только мейнтейнер (Артём Сафро) через PR; merge, push в `main` и force-push — его действия, не твои.
5. Перед новым сценарием проверь, что уже сделали коллеги (реестр и ветки). Дубль допустим, причина записывается в паспорт.
6. Вопросы — одним пакетом до 5, к каждому своя рекомендация. Факты, которые можно найти в репозитории, ищи сам.
7. Различай замерено / оценено / предположение. Запуск в Max, Blender или Синтезе заявляй только если реально запускал.

## Где что лежит

| Что | Где |
|---|---|
| Команда и id | `team.md` |
| Пайплайн, доли времени, фокус | `roadmap/pipeline.json`, описание — `roadmap/README.md` |
| Паспорта и состояние задач | `sessions/` (шаблон `templates/ntr/session.md`) |
| Сценарии с версиями | `scenarios/<автор>_<тема>_<исходник>_<dcc>_v<X.Y.Z>.md` |
| Тулзы | `tools/` |
| Реестр и отчёты о применении | `registry/tools/`, `registry/tests/` |
| Дашборд (генерируется, руками не править) | `STATUS.md`, `status/` |
| Задачи (снимок Trello) | `roadmap/backlog.json` |
| Памятка для людей | `docs/team-memo.md` |
