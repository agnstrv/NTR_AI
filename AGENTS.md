# NTR — правила для агента (v2, черновик)

Ты работаешь в общем репозитории команды NTR (цифровые двойники: НПМ, упрощённый НПМ, ВПМ; Ground и ОКС).
Аккаунт Codex и GitHub общий на всю команду, поэтому авторство и смысл работы фиксируешь ты.

## Вход в любую сессию — всегда, до любой работы

Запусти скилл `ntr-start`. Он по шагам:
1. **Кто ты?** Спроси имя, сверь с `team.md`. Если на ПК есть файл `.ntr-user` — предложи это имя.
2. **Что делаем?** Один из четырёх режимов:
   - `discuss` — обсуждение, идеи, разбор → скилл `ntr-discuss`
   - `contract` — контракт для агента (задача, которую решает только нейросеть: анализ исходников, коллизии…) → `ntr-contract`
   - `tool` — скрипт / тулза для Max или Blender → `ntr-tool`
   - `apply` — применить готовый инструмент коллеги на своём проекте → `ntr-apply`
3. **Где в пайплайне?** Ячейка и этап из `roadmap/pipeline.json` (например `ground-npm` / `flora`).
4. **Что уже есть?** Прочитай `registry/tools/` по этой ячейке/этапу и покажи человеку: что есть, чьё, статус, кто тестировал. Сверь с фокусом в `roadmap/pipeline.json`. Предложи путь: применить / доработать чужое / делать своё — с рекомендацией.
5. Выведи **одной строкой** метку сессии (по ней строится отчётность, не пропускай):
   `NTR-SESSION user=<id> mode=<mode> cell=<cell> stage=<stage> task="<коротко>"`

## Правила

1. Исходные файлы проекта не трогать. Работать только с копиями. Клиентские модели, альбомы и текстуры в GitHub не кладём.
2. Без выбранного режима и метки `NTR-SESSION` работу не начинать.
3. Перед созданием нового — проверить реестр. Не дублировать существующий инструмент без причины, причину записать.
4. Работать только в своей ветке `work/<user>/<тема>`. **Никогда** не делать merge, push в `main` и force-push. В `main` вливает только мейнтейнер (Артём Сафро) через PR.
5. Неясное — спроси. Вопросы задавай одним пакетом, не больше 5, к каждому — своя рекомендация. Факты, которые можно найти самому, ищи сам.
6. Сначала короткий пилот (20–40 мин работы), показать человеку, потом остальное.
7. Различать: замерено / оценено / предположение. Время «до» и «после» пиши с пометкой, как получено. Не заявляй, что запускал Max/Blender/Синтез, если не запускал.
8. Конец работы — скилл `ntr-submit` («сдаю»): шаблон режима заполнен, реестр обновлён, коммит и PR в свою ветку, текст для чата команды, строка `NTR-RESULT`.
9. Если контекст сессии заполнен больше чем на ~40% — предложи `ntr-submit` (или сохранить состояние) и новую сессию.

## Где что лежит

| Что | Где |
|---|---|
| Команда | `team.md` |
| Пайплайн, доли времени, фокус | `roadmap/pipeline.json`, описание — `roadmap/README.md` |
| Реестр инструментов и контрактов | `registry/tools/<id>.md` |
| Отчёты о применении (кросс-тесты) | `registry/tests/` |
| Заметки обсуждений | `notes/` |
| Шаблоны | `templates/ntr/` |
| Отчётность (генерируется, руками не править) | `STATUS.md`, `status/` |
| Задачи (снимок Trello) | `roadmap/backlog.json`; ведение Trello — только по скиллу `ntr-trello-sync` |
| Памятка для людей | `docs/team-memo.md` |
