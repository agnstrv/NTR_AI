# Инструкции для Codex

- Сначала читай `README.md` и относящиеся к задаче материалы в `process/`, `standards/`, `templates/`.
- Отличай подтверждённое требование от чернового наблюдения. Не превращай параметры из интервью в обязательные проверки без ссылки на утверждённое ТЗ.
- Определи режим: структура, документация, эксперимент или работа по объекту. Для структуры не требуй полный производственный цикл; для отдельного эксперимента запрашивай только нужные входы и эталон.
- При работе по объекту проверь ссылку на Google Drive, паспорт, тип результата и применимый комплект. Не выбирай «самый новый» файл только по имени.
- Проверь resources/ и process/workflows.md. Папка назначения и заявленный ресурс не равны полученному файлу; не выдумывай ссылки и версии.
- Работай с копией клиентских файлов. Не удаляй и не перезаписывай полученные исходники.
- Для автоматизации укажи входы, выходы, версии программ, ограничения, способ проверки и откат.
- Изменение общего стандарта и перенос скрипта из эксперимента требуют проверки человеком команды.
- Не помещай в репозиторий клиентские файлы, секреты и большие бинарные модели.

- Для продолжения используй process/codex-start.md, templates/automation-experiment.md и templates/handoff.md. Не отмечай проверку исполнителем как выполненную без его фактического результата.
