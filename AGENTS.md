# NTR — правила для агентов
1. Прочитай README.md, process/repository-structure.md и process/team-workflow.md. Затем только материалы своей задачи.
2. Определи режим: первичный сбор / новая разработка / продолжение / проверка / производство по объекту. Для документации не требуй модель.
3. Проверь git status, текущую ветку, origin и доступ. Fetch не обновляет рабочие файлы. Сверь правила с origin/main; сохраняй чужие и незакоммиченные изменения. Конфликтующие инструкции согласуй.
4. Следуй process/agent-harness.md: исследование → grill → критерии/архитектура/фазы → реализация → проверки → отдельный AI-review → передача → commit + push.
5. Неразрешённые решения выясняй у человека; доступные факты ищи сам. Уже согласованное не переспрашивай.
6. Сопоставляй работу с ID Trello и каталогом tools/README.md. Не дублируй существующие инструменты, карточки или открытые PR.
7. Новые пути — ASCII латиница, kebab-case; существующие канонические пути и ID сохраняй; карту миграции смотри в process/repository-migration.md. Авторство — в ветке и README; инструмент не переименовывается при передаче.
8. Ветка: work/<author>/<tool>/<job-id>; одна задача — одна ветка. Worktree — по необходимости. Никаких прямых push в main, force push или удаления чужой истории.
9. Субагентам назначай независимые задачи и непересекающиеся области записи. Не допускай одновременного управления одной сценой Blender/Max. При отсутствии субагентов выполни этапы последовательно и укажи ограничение.
10. Клиентские модели, альбомы, текстуры, секреты и большие бинарные файлы не входят в GitHub. Работай на копиях; ссылки и версии — в resources/cases. Не считай .gitignore достаточной проверкой содержимого.
11. Различай утверждённое ТЗ, наблюдение и гипотезу. Не переноси численные нормы между кейсами без источника. Не выбирай актуальный альбом только по имени файла.
12. Фиксируй версии ПО, параметры, фактический результат и ограничения. Не заявляй запуск Blender/checker, если он не выполнен.
13. Автор публикует commit + push. При слиянии нужен PR и решение проверяющего человека; отдельное одобрение координатора не требуется. AI-review не заменяет приёмку человеком.
14. Проверяющий может принять документацию исследования в main без признания инструмента готовым. accepted требует проверки на проекте коллеги, отчёта и области применимости.
15. Изменение кода проверяющим требует другого человека для приёмки. Мелкие правки инструкции без изменения поведения он может принять сам.
16. Сохраняй handoff и ссылки Trello/commit/PR. Без доступа к Trello подготовь точный текст обновления, не сообщай об успешной синхронизации.
17. Навыки Matt и их версия: process/agent-skills.md. Они дополняют эти правила, но не меняют утверждённые роли, хранилища и полномочия.
18. НПМ ОКС по сценарию Ромы: прочитай process/npm-oks-routing.md; сохрани выбор лёгкой/средней версии и согласованный объём.
19. Сообщение `/push` (в том числе с уточнением объёма) означает публикацию наработок текущего чата: прочитай и выполни `.agents/skills/push/SKILL.md` от корня репозитория. Правило действует во всех подпапках NTR_AI; обсуждение или создание команды не запускает её.
