# Предложение v2: как устроен репозиторий NTR (черновик для обсуждения 09.11)

Ветка `proposal/v2-harness`, локально, не опубликована.

## Почему меняем
Основа v1 (13.10) хорошая, но процесс не прижился: всё публикуется с общего аккаунта без авторства, 7 инструментов застряли в ветках, ничего не прошло проверку коллегой, `main` не менялся с 13.10, метрик нет. Причина — процесс тяжёлый для людей и невидимый для руководителя.

## Что добавлено
| Что | Файл | Зачем |
|---|---|---|
| Роутер для агента | `AGENTS.md` (~9 правил вместо 18) | кто → режим → этап → что уже есть → работа → «сдаю» |
| 6 скиллов Codex | `.agents/skills/ntr-*` | вход, 4 режима (обсуждение / контракт / тулза / применить готовое), «сдаю» |
| Команда | `team.md` | авторство при общем аккаунте |
| Карта пайплайна | `roadmap/pipeline.json`, `roadmap/README.md` | 5 ячеек, Ground-НПМ расписан с долями, фокус периода |

## Что предлагается заморозить (не удалять)
`process/*` кроме нужного, NAV-001, 26 Issues (дублируют Trello/реестр), `tasks/*/registry.json`, правило «третьего проверяющего», дубли маршрутизации НПМ ОКС. Ссылки из нового `AGENTS.md` на них убраны.

## Что проверено
- `ntr-daily.ps1` на синтетических сессиях: отбирает только сессии в папке репозитория (включая worktree), пропускает субагентов и чужие папки, читает метки `NTR-SESSION` / `NTR-RESULT`.
- `ntr-status.ps1` на реальном реестре и на демо-данных; дашборд открывается без ошибок.

## Что не проверено
- Скиллы в реальном Codex у ребят (как Codex подхватывает `.agents/skills` и следует роутеру).
- Публикация журнала в ветку `journal` (`-Push`) — не запускалась.
- Расписание (Codex automation / Планировщик Windows) не настроено.

## Решения, нужные от компании / Сергея
1. Сделать репозиторий **приватным** (журналы и метрики содержат названия проектов).
2. Открыто сказать команде, что сессии автоматически сводятся в отчёт.
3. Время на работу с ИИ — явной строкой в оценке проектов.
4. Доступ к Trello не через одного человека.

## Первые две недели (09.11–22.11)
1. Созвон-онбординг: `.ntr-user`, первый вход через `ntr-start`, вечерняя сводка на каждом ПК.
2. Слить ветки с инструментами в `main` как `draft` — чтобы их было видно.
3. Сверить с командой доли Ground-НПМ; владельцы описывают остальные 4 ячейки.
4. Фокус: флора + МАФы. Каждый применяет минимум один чужой инструмент на своём проекте.
5. Еженедельно: `ntr-status.ps1` → статус для встречи с Сергеем.
