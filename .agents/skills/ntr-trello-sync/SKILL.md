# Синхронизация Trello ↔ репозиторий

**Источник правды — репозиторий**, Trello — его зеркало для людей.
- Станции и доли времени: `roadmap/pipeline.json`
- Задачи: `roadmap/backlog.json`
- Инструменты и статусы: `registry/tools/*.md`, проверки: `registry/tests/`
- Факт работы: журналы `journal/` (ветка `journal`)

Если Trello и репозиторий расходятся — прав репозиторий. Исключение: человек сам передвинул карточку → спроси у него и перенеси изменение в репозиторий через `ntr-retro`.

## Структура доски

**Колонки — только эти, в этом порядке** (не создавать новых):
`📌 Обзор` · `⛔ Нужна помощь` · `🔵 В работе` · `🟣 Проверка коллегой` · `🟢 Готово к применению` · `🔴 Очередь P1` · `🟡 Очередь P2` · `⚪ Позже P3`

Соответствие статусам `backlog.json`: help · in-progress · review · ready · queue (P1/P2/P3).

**Карточка = станция или задача станции**, не микрошаг.
- Название: `<ЯЧЕЙКА> · <этап> · <что получить>`, например `ground-npm · flora · расстановка по ведомости и рельефу`.
- Микрошаги (было отдельными карточками) — **чек-лист внутри карточки**, не новые карточки.
- Исполнитель — участник карточки (members), а не суффикс «---АН» в названии. Код из `team.md` допустим только как временный, пока у человека нет аккаунта Trello.
- Метки (labels): ячейка (`ground-npm`, `oks-vpm`…), линия (`контракт` / `тулза`), `фокус` — если станция в `focus` из `pipeline.json`.
- В описании карточки — ссылки: карточка реестра `registry/tools/<id>.md`, ветка, PR.

## Что делать при синхронизации

1. Прочитай `roadmap/backlog.json`, `pipeline.json`, `registry/`, свежие журналы и (если есть) расшифровку встречи.
2. Составь **план изменений** списком: создать / переместить / объединить / закрыть / обновить чек-лист — с причиной для каждого.
3. Покажи план человеку и дождись «да». Без подтверждения в Trello ничего не меняй.
4. Применяй изменения только если у тебя реально есть доступ к Trello (коннектор или браузер с входом). Нет доступа — отдай план текстом и не сообщай, что синхронизировал.
5. Обнови `roadmap/backlog.json` (поле `snapshot` = сегодня) и сдай через `ntr-retro`.

## Нельзя
- Создавать карточки без ячейки и этапа. Если этапа нет в `pipeline.json` — сначала предложить дополнить карту.
- Дробить работу на карточки мельче станции.
- Двигать карточку в «Готово к применению», если в реестре нет статуса `cross-tested` или выше.
- Удалять карточки — только архивировать, и только по подтверждению.
- Переносить личные/непроектные темы из чатов.

## После встречи (по расшифровке Zoom)
Вытащи решения и поручения → сопоставь со станциями → план изменений карточек (кто, что, срок) → подтверждение → применить → `backlog.json`.
