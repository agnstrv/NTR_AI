# Реестр инструментов и контрактов

Одна карточка = один файл `tools/<id>.md`. Один отчёт о применении = один файл `tests/<дата>-<tool>-<user>.md`.
Отдельные файлы — чтобы шесть человек в своих ветках не конфликтовали при слиянии.
Сводную таблицу собирает `scripts/ntr-status.ps1` в `STATUS.md` — руками её не правим.

## Поля карточки

| Поле | Значения |
|---|---|
| `line` | `contract` — контракт для агента · `tool` — скрипт/тулза · `infra` — инфраструктура команды |
| `author` | id из `team.md` |
| `cell`, `stage` | ячейка и этап из `roadmap/pipeline.json` (`-`, если не привязан) |
| `dcc` | `max` · `blender` · `any` |
| `status` | см. ниже |
| `where` | где лежит: `main: путь`, `ветка: имя` или «локально у …» |
| `minutes_before`, `minutes_after` | время этапа на типовом объёме без и с инструментом |
| `time_source` | `measured` (замер на проекте) или `estimate` |

## Жизненный цикл

| Статус | Значит | Кто ставит |
|---|---|---|
| `not-in-repo` | известно, что существует, но в репозитории нет | мейнтейнер |
| `draft` | автор пользуется сам | автор |
| `measured` | есть замер времени до/после на реальном проекте | автор |
| `cross-tested` | минимум один коллега применил на своём проекте (есть отчёт в `tests/`) | агент по отчёту |
| `accepted` | минимум два отчёта без блокеров, принят в `main` | **только мейнтейнер, человек** |

В итоговую экономию для отчёта идут только `measured` и выше с `time_source: measured`.

## Отчёт о применении (`tests/`)

Создаётся в режиме `apply` по шаблону `templates/ntr/test-report.md`: кто, какой проект, результат (`ok` / `issues` / `fail`), затыки, время.
