# Протокол 2. Копия меша, UV, запекание и карты

Версия 1.0 · 01.10.2026 · NPM-WINDOWS-001

## Статус и входы

Повторено на мешах 001, 002 и 003; результаты визуально одобрены Ромой. Исполнитель — Codex. Параметры ниже заданы Ромой для текущего процесса; они не заменяют общее ТЗ НПМ. [Протокол окон](01-window-cleanup.md) · [рабочие процессы](../../process/workflows.md) · [статус общего стандарта](../../standards/npm.md).

Среда: Windows, Blender 5.2.2 LTS по ответу приложения, Cycles, MCP-аддон 1.8 / протокол 13.

Входы: исходный меш с корректными материалами и UVMap, согласованные текстуры и маски стекла, название проекта, разрешение на этап подготовки домика. Для нового перехода после окон спросить Рому; поручение всего цикла уже является разрешением.

## 1. Подготовка копии — порядок обязателен

1. Создать независимую копию объекта и данных меша в том же мировом положении. Оригинал сохранить.
2. Удалить все слоты материалов только у копии.
3. Создать один новый материал и назначить всем граням копии.
4. Сразу добавить пустую текстуру 2048×2048 без альфа-канала и Image Texture. Сделать этот нод активным для запекания.
5. Только после этого выполнить Smart UV Project.

Пример имён: 003_UV, 003_Atlas, 003_Atlas_BaseColor. Это соглашение об именах, а не команда перезаписать уже существующий объект.

## 2. Развёртка

- Одна UVMap и один тайл UDIM 1001 для итогового атласа.
- Все острова внутри тайла.
- Минимум 8 пикселей между островами при 2048×2048.
- Минимум 15 пикселей от каждого края тайла.
- Подгонять масштаб равномерно; после упаковки проверять фактические расстояния.

Внутренняя область тайла: [15/2048; 1−15/2048] по U и V. Настройка отступа в операторе не заменяет измерение результата.

В испытании использовали Smart UV Project с углом 66° и упаковку с долей 9/2048, затем центрирование/равномерную подгонку. Это проверенный стартовый профиль; критерии приёмки — фактические расстояния и отсутствие недопустимых наложений. Текущий измеритель оценивал межостровные расстояния по границам; полноценный независимый checker геометрии не запускался.

## 3. Запекание цвета

1. Выделить исходник, затем копию; копия активная.
2. Render Engine — Cycles; Bake Type — Diffuse.
3. Contributions: только Color; Direct и Indirect выключены.
4. Selected to Active включён; Cage выключен.
5. Extrusion — 1 метр с учётом единиц сцены. При обращении через API: 1 / scale_length.
6. У копии активен нод целевой пустой текстуры.
7. На время bake отключить выход целевого изображения от шейдера, после завершения восстановить связь.
8. Выполнить bake и проверить успешное завершение и изображение.
9. Сохранить исходный запечённый атлас отдельно до белой заливки.

В испытании Bake Margin = 8 px при фактических зазорах около 18 px. Если зазор изменяется, проверить, что расширение краёв соседних островов не конфликтует. Условия «зазор ≥8» и «Margin 8» нельзя автоматически считать достаточными вместе.

Если для запекания нужны исправленные варианты исходных изображений, использовать рабочие копии и гарантированно восстановить исходные связи после bake. Временные объекты, материалы и изображения очищать после операции, в том числе при ошибке.

## 4. Маска в UV итогового атласа

1. Перенести согласованные маски с исходной UV-развёртки в UV копии отдельным запеканием маски. Нельзя просто растянуть исходные маски до 2048×2048.
2. Для неостеклённых материалов использовать чёрный цвет.
3. Ограждения перед стеклом включить целиком, сохранив рамы и глухие панели по протоколу 1.
4. Применять уточнённую маску к сохранённому атласу до заливки.
5. Не использовать грубую бинаризацию, уничтожающую тонкие перемычки. Центры стёкол — чисто белые, по краям плавное сглаживание, при нулевой маске исходные пиксели неизменны.
6. Проверить увеличенные участки с тонкими делениями и ограждениями.

В проверенных запусках применялся плавный переход для значений перенесённой маски от 200 до 248: ниже — 0, выше — 255, между ними smoothstep. Это настройки конкретного способа экспорта маски; они не универсальны для другой гаммы, изображения или метода переноса.

## 5. Карты и подключение

Пусть M — проверенная маска стекла в диапазоне 0…255.

| Файл | Содержание | Подключение |
| --- | --- | --- |
| NAME.png | Цветной атлас, белое стекло | Color → Base Color |
| NAME_m.png | M: стекло белое, остальное чёрное | Color → Metallic |
| NAME_r.png | 255 − M | Color → Roughness |
| отдельный GlassMask.png | Копия рабочей маски | Сохранить для повторных правок |

Карты _m и _r — Non-Color; цветной атлас — sRGB. Использовать одинаковую UVMap и согласованные параметры отображения. Обе карты подключать сразу после создания в Principled BSDF материала копии. Схема карт — условие данного процесса, а не универсальное описание любого материала стекла.

Итоговые PNG: 2048×2048, RGB, без альфа. Внутреннее свойство channels Blender может показывать 4; дополнительно проверять параметры создания, глубину RGB24 и фактический сохранённый PNG.

## 6. Сохранение, проверка и откат

Все меши одного Blender-файла используют одну папку «итоговые текстуры» внутри папки проекта. Не создавать отдельную папку для каждого bake. Имена файлов должны различать меши. Исходники, рабочие маски и резервные версии сохранять отдельно.

Проверить размер/каналы PNG, белые центры стекла, сохранность делений, панелей и дверей, неизменность вне маски, равенство _m + _r = 255, Non-Color и фактические связи нодов. Сверить результат на материале и увеличенном фрагменте.

Упаковка изображений в Blender не заменяет сохранение PNG и .blend. В выполненном испытании PNG сохранены и изображения упакованы; .blend не сохранялся. Сохранение сцены указывать явно в передаче результата.

Откат: вернуть резервные изображения и подключения либо удалить только созданную копию. Не удалять исходный меш и его материалы.
