# VPM-GRID-001 — нарезка ВПМ, UV и UDIM в Blender

GitHub-задача: [#26](https://github.com/agnstrv/NTR_AI/issues/26).
Статус на 05.10.2026: испытано на кубе, сложном фасаде и нескольких частях одной рабочей сцены. Код остаётся экспериментом; независимая приёмка командой и перенос в общий инструмент не выполнены.

[Протокол](experiment.md) · [Передача](handoff.md) · [Код](scripts/) · [Обезличенные отчёты](reports/) · [Синтетическая проверка](synthetic_check.py).

## Задача

Разрезать весь меш плоскостями общей XYZ-сетки поверх существующих рёбер; повторить UV внутри выбранного UDIM; сохранить соседнюю геометрию и её UV; согласовать вершины на стыках. Дополнительные этапы: сопоставление цвета с НПМ, оконные/дверные углубления и исправление отражённых UV.

Клиентские названия заменены алиасами `Main`, `VPM`, `VPM.006`, `VPM.009`, `VPM.010`. Модели, текстуры, скриншоты, мировое положение объекта и подробная геометрия границ в GitHub не опубликованы. В [manifest.json](manifest.json) записаны хеши исходных и опубликованных скриптов и изменения для публикации.

## Среда и установка

Проверено: Windows, Blender **5.0.0**, Python 3.11.13 внутри Blender; `bpy`, `bmesh`, `mathutils`, встроенный NumPy. Другие версии не проверены. Нижняя версия в `bl_info` аддона означает заявленную совместимость, а не результат испытания.

Скопировать всю папку `scripts/` в отдельную доступную для записи рабочую папку. Модули загружают соседние файлы; отчёты и выходные `.blend` записываются рядом со скриптами. В начале работы сохранить отдельную копию сцены. Производственные исходники не перезаписывать. Дополнительные аддоны не нужны.

`vpm_auto_uv.py` можно установить как legacy add-on или запустить как файл. Панель: 3D View → Sidebar → VPM. При установке в виде пакета нужны `__init__.py` из `vpm_auto_uv.py` и соседний `vpm_cut_weld_main009.py`. Установка не объединяет остальные этапы в одну кнопку.

Для переименования обрабатываемого объекта изменить `NAME`/`PART` или имена входов в своей копии скрипта. Эти версии содержат конкретные алиасы и параметры опыта, не являются универсальным интерфейсом для произвольной сцены.

Запуск файла в Python Console Blender:

```python
import runpy
runpy.run_path(r"C:\work\vpm\vpm_cut_main006_1004.py", run_name="__main__")
```

Путь — пример; указать реальную рабочую папку. Вариант без автоматического сохранения `.blend`:

```python
module = runpy.run_path(r"C:\work\vpm\vpm_cut_main006_1004.py")
report = module["run"](save_path=None)
```

Для отражений используется `run(save=False)`. JSON-отчёты всё равно записываются. Проверять активный объект, видимость и целевой UDIM до запуска. Не выполнять все скрипты подряд на уже готовом меше: отдельные этапы меняют входные условия следующего и не все повторные запуски защищены.

## Параметры именно этого опыта

Базовый режим: 2048 px, 1000 px/м → шаг 2.048 м. Профиль фасада: высота 19.3 м / 8 = 2.4125 м → плотность около 848.912 px/м. Эти два профиля различаются; 8 рядов не сохраняют 1000 px/м автоматически.

Финальные операции по отдельным частям используют полный шаг по XYZ, без деления квадрата на четыре. Начало сетки — локальное начало `Main`, его линейная матрица должна быть единичной. Масштаб сцены учитывается при расчёте шага. В проверенных сценах масштаб единиц = 1; согласование границ использует 0.001 единицы координат, поэтому другой unit scale требует отдельной проверки допуска.

UDIM 1004: U от 3 до 4, V от 0 до 1. Точки на правой/верхней границе допустимы как границы острова; принадлежность проверять по центру полигона.

## Повторение без клиентских данных

Из отдельного процесса Blender:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.0\blender.exe' --background --factory-startup --python-exit-code 1 --python .\synthetic_check.py
```

Проверка сбрасывает свою сцену, создаёт синтетические плоскости и однотонную UDIM-карту в `.synthetic-work/`. Выполняет оба скрипта частей и исправление зеркальной UV. Результат: [reports/synthetic_check.json](reports/synthetic_check.json). Это проверка переносимости опубликованного кода, а не эталон полного фасада или плиточных швов.

## Проверка и откат

После запуска осмотреть сетку, углы, стыки, глубину проёмов, плотность и все используемые UDIM; убедиться в отсутствии скрытых промежуточных объектов. Для mirror дополнительно проверить швы именно используемой карты и normal map, если она есть. Автоматический подбор уменьшает различие рисунка, но не гарантирует точного совпадения асимметричной текстуры после отражения.

Откат: открыть сохранённую копию до этапа. Не полагаться на один Ctrl+Z для последовательности Python-операций. Проверка геометрии и UV в отчётах не заменяет производственную приёмку, UCX/FBX/GeoJSON, нормативную проверку или исправление всех исходных non-manifold рёбер.
