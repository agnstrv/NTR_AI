# Памятка команды: GitHub и локальный агент
## С чего начать
GitHub хранит общие правила, код и историю. Trello отвечает на вопрос «кто и что делает». Drive хранит проектные модели и результаты.
Каждый работает на своём ПК под своим GitHub-аккаунтом с доступом к NTR_AI. Доступ к репозиторию, Trello, Drive и Blender/Max проверяется отдельно.
Откройте в Codex или Claude Code именно папку репозитория либо worktree. Начните с промпта 1 для накопленных работ, с промпта 2 — для новой задачи.

## Слова на практике
| Действие | Что происходит |
|---|---|
| clone | Первый раз скачиваем репозиторий с историей |
| fetch | Узнаём новые коммиты и ветки GitHub; рабочие файлы не изменяются |
| origin/main | Последнее полученное через fetch состояние main на GitHub |
| branch | Отдельная линия изменений задачи |
| switch | Переключаем рабочую папку на ветку |
| commit | Сохраняем выбранные изменения локально |
| push | Публикуем локальные коммиты в GitHub |
| pull | Получаем изменения и интегрируем их в текущую ветку |
| PR | Предлагаем включить изменения одной ветки в другую |
| merge | Объединяем историю и изменения |
| worktree | Дополнительная рабочая папка того же локального репозитория для другой ветки |

Fetch не равен обновлению открытых файлов. Commit без push коллега не увидит. Worktree не отправляется в GitHub: отправляются коммиты ветки.

## Первый запуск на ПК
Установите Git и выбранного локального агента, войдите в свои аккаунты, проверьте доступ к репозиторию. Действующие проекты не удаляйте.
Команды ниже выполняются в терминале. Имена веток — примеры, их нужно заменить на свою задачу.

~~~sh
git clone https://github.com/agnstrv/NTR_AI.git
cd NTR_AI
git status
git fetch origin
~~~

Откройте NTR_AI в агенте. Попросите назвать прочитанные правила, текущую ветку и доступные инструменты. Корневой AGENTS.md должен быть из согласованного main; Claude получает указатель через CLAUDE.md. Проверьте навыки по agent-skills.md.
Для первичного сбора используйте [промпт 1](../prompts/01-collect-local-work.md), указав реальные рабочие папки.

## Новая задача
1. Выберите карточку Trello, найдите существующий инструмент.
2. Сохраните текущую работу. Агент проверяет status и получает main.
3. Создайте свою ветку. Для нового независимого задания:

~~~sh
git fetch origin
git switch -c work/roman-kasyan/npm-window-bake/trello-example-first-test origin/main
~~~

4. Откройте [промпт 2](../prompts/02-start-or-continue.md). Укажите входы и результат.
5. Ответьте на оставшиеся вопросы агента. Он оформит фазы, выполнит работу и проверки.
6. Передайте коллеге ссылку на ветку, commit, job и инструкцию. Исходные модели — ссылкой Drive.

Если ветка уже существует, продолжайте её; не создавайте дубликат и не перезаписывайте.

## Как забрать разработку коллеги
Получите точное имя ветки/commit из Trello. Fetch сам не переключает папку:

~~~sh
git fetch origin
git branch -r
~~~

Попросите агента создать вашу ветку проверки от найденной ветки коллеги. Пример, только если такая исходная ветка действительно существует:

~~~sh
git switch -c work/ivan-proselkov/npm-window-bake/trello-example-review origin/work/roman-kasyan/npm-window-bake/trello-example-first-test
~~~

Проверьте на копии своего проекта. Запишите версию кода, среду, результаты и ограничения. Если принимаете, скажите агенту: «Проверил commit … на кейсе …, принимаю для …; оформи PR и включи в main». Сам факт этой фразы не заменяет выполненную проверку.
Если вы изменили код, пусть изменённую версию проверит другой человек.

## Две задачи одновременно
Используйте разные worktree; команды выполняйте из репозитория. Путь ../NTR_AI-ramp — новая свободная папка:

~~~sh
git fetch origin
git worktree add -b work/ivan-proselkov/ground-ucx/trello-example-ramp ../NTR_AI-ramp origin/main
~~~

Откройте новый чат в NTR_AI-ramp. Worktree имеют разные рабочие файлы, но общую Git-базу; не удаляйте их обычным удалением папки. После окончания пусть агент проверит сохранность и уберёт ненужный worktree штатно.
Сцены Blender/Max и клиентские данные сами по себе worktree не изолирует: отдельные копии/сеансы нужны явно.

## Публикация и завершение дня
Отправьте агенту `/push`, чтобы опубликовать наработки текущего чата по [проектному сценарию](../.agents/skills/push/SKILL.md). При необходимости уточните объём после команды. [Вызов в Codex и Claude Code](agent-skills.md#команда-проекта-push).

Агент просматривает diff, добавляет только нужные файлы, делает commit и push. Сверьте, что опубликован правильный результат. В конце дня handoff должен объяснять, где остановились и что сделать следующим.
После принятия работы другой человек получает новую версию main:

~~~sh
git status
git switch main
git pull --ff-only origin main
~~~

Этот пример — для чистой рабочей папки. Если есть незакоммиченная работа или Git сообщает расхождение, не удаляйте её: поручите агенту разобрать ситуацию. Обновление main не обновляет автоматически другие рабочие ветки.

## Если что-то не работает
| Ситуация | Действие |
|---|---|
| Нет доступа к GitHub | Проверить свой аккаунт и приглашение; не передавать пароли |
| Агент не видит Blender | Проверить доступный мост/инструмент; не считать моделирование выполненным |
| Нет Trello | Сохранить точный текст обновления в handoff |
| Нет навыка | Прочитать локальный SKILL.md по agent-skills.md; сообщить, что native-вызов не настроен |
| Конфликт Git | Сохранить обе версии, понять смысл изменений, согласовать неоднозначность |
| Чужой файл изменён | Не откатывать автоматически; выяснить источник |
| Работа не готова | Опубликовать в ветке с честным статусом и следующим шагом |
