# Как начать и продолжить задачу с Codex

Для командной разработки используйте [два общих промпта](../prompts/README.md), [памятку](team-quickstart.md) и [блок-схемы](../docs/team-workflow/README.md). Ниже — предметные сценарии и работа по объекту.

1. Откройте [каталог](../resources/README.md) и [подходящий процесс](workflows.md).
2. Выберите одну задачу: структура / документация / эксперимент / работа по объекту. Для структуры не нужен полный комплект проекта; для эксперимента нужны только относящиеся к нему входы.
3. Передайте Codex текст задачи, README/AGENTS, выбранный процесс, ссылку на разрешённые входы, эталон, версии ПО и критерий результата. Если connector не открывает ссылку, приложите разрешённый файл в чат.
4. Работайте на копии. Сохраняйте результаты на Drive, код и протокол — в GitHub по согласованному процессу.
5. Заполните [эксперимент](../templates/automation-experiment.md) и [передачу](../templates/handoff.md). Незакрытая проверка явно остаётся незакрытой.

## Стартовый текст

> Задача: [одна конкретная операция]. Режим: [структура / документация / эксперимент / проект]. Прочитай README, AGENTS и [процесс]. Входы: [ссылки/файлы и версии]. Эталон: [ссылка]. Применимые требования: [источник, пункт, область; неизвестное отметить]. Среда: [редактор/версия/аддоны]. Ожидаемый результат: [файл и место]. Проверка: [критерии]. Работай на копии, не додумывай отсутствующие нормы. Сохрани параметры, время, проверки, исправления и следующий шаг так, чтобы другой коллега мог продолжить.

Для NAV-001 вместо моделей используются учебные метаданные; цель — две корректные карточки, заполненный протокол и передача коллеге. [Начать проверку навигации](navigation-pilot.md).

## Выбор сложности проекта НПМ ОКС

На сообщение «моделирую НПМ ОКС» (также «моделирую ОКС НПМ», «работаю с НПМ ОКС» или «работаю с ОКС НПМ») спросить: «Какая сложность у проекта — лёгкая или средняя?» Если сложность уже указана, повторно не спрашивать.

Ответ «лёгкая», «лёгкая геометрия» или «простой» выбирает папку `Рома. НПМ ОКС/НПМ. Легкая версия/`. Ответ «средняя», «средняя геометрия» или «средний» выбирает папку `Рома. НПМ ОКС/НПМ.Средняя версия/`. Перед работой прочитать README выбранной папки и выполнять её сценарии в установленном порядке. Если пользователь не знает сложность, помочь определить её по доступной архитектуре; не выбирать папку наугад.

## Простой сценарий Ромы для ОКС НПМ

Ответ о сложности «лёгкая» / «лёгкая геометрия» / «простой» запускает [НПМ. Легкая версия](<../Рома. НПМ ОКС/НПМ. Легкая версия/README.md>): сначала очистка окон и подготовка маски стекла, затем копия меша, UV, запекание и карты, включая выдавливание нижнего контура на 2 метра. Прочитать оба протокола до работы. Если сценарий уже указан, повторно не спрашивать. Выбор простого сценария разрешает оба этапа; уточнять только недостающие входы и неоднозначные участки.

## Средний сценарий Ромы для ОКС НПМ

Выбор «средний» запускает [НПМ.Средняя версия](<../Рома. НПМ ОКС/НПМ.Средняя версия/README.md>). Когда архитектура доступна в Blender, спросить «Приступаем?». После подтверждения и указания проекта и корпуса осмотреть его и рекомендовать лёгкий либо сложный подход по фактической геометрии. Уже полученные ответы повторно не спрашивать. Для смешанного корпуса назвать основной подход и участки с отдельной обработкой. Прочитать соответствующий протокол; сложный подход начинается с показа характерного участка перед распространением решения.

После проверки моделирования следующий этап полного среднего сценария — [«Запекание по средней проработке архитектуры»](<../Рома. НПМ ОКС/НПМ.Средняя версия/03-bake-and-maps.md>). Перед новым мешем уточнить необходимость прозрачности и материал, если ответа ещё нет. Затем выполнить совмещение UV, подготовку карт, проверку артефактов и финальную выдачу по этому протоколу.
