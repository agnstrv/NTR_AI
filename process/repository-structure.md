# Структура технической базы NTR
Согласовано с командным координатором 13.10.2026. Текст инструкций — русский; все новые имена путей — ASCII латиница. Миграция существующих разработок от 13.10.2026 описана в repository-migration.md.

## Направления
| Путь | Назначение |
|---|---|
| tools/collisions/<tool>/ | UCX земли и зданий |
| tools/uv/<tool>/ | UV, UDIM, нарезка, тексель |
| tools/textures/<tool>/ | Bake, атласы, маски и карты |
| tools/geometry/<tool>/ | Оболочки, МАФ, рамы, вырезы |
| tools/placement/<tool>/ | Растения, МАФ, окна, светильники |
| tools/validation/<tool>/ | Проверка результата |
| tools/export/<tool>/ | Экспорт и упаковка |
| tools/infrastructure/<tool>/ | Общие средства разработки и интеграции |
| process/ | Общие правила и памятки |
| prompts/ | Два стартовых промпта |
| templates/ | Шаблоны записей |
| standards/ | Подтверждённые требования с источниками |
| resources/ | Каталог внешних материалов |
| tasks/<author>/ | Личные указатели на задачи, без копий кода |
| .agents/skills/ | Зафиксированные навыки агентов |

НПМ/ВПМ и Blender/Max — свойства инструмента, а не обязательные дубли дерева. Один инструмент может иметь несколько ID Trello; один ID может потребовать нескольких jobs. Новые направления добавлять только при отсутствии подходящего.

## Папка инструмента
Пример: tools/collisions/ground-ucx/.
- README.md: автор, участники, назначение, статус, среда, запуск, область применения, ID/URL Trello.
- src/: общий код и исходники аддона. Имя пакета Python может использовать underscore.
- workflow.md: сценарий выполнения агентом, если нужен.
- docs/: требования, архитектура, решения, известные ограничения.
- jobs/<job-id>/: конкретная разработка/доработка: task.md, plan.md, handoff.md, review.md по необходимости.
- cases/<case-id>/: воспроизводимый опыт: case.md с входами, параметрами, ожидаемым/фактическим результатом и ссылками на отчёты.
- tests/: автоматические проверки.
- resources.md: внешние материалы и их версии.

Пустые файлы ради шаблона не создавать. Исходники кода — src/, исходные модели заказчика — Drive. Тяжёлые результаты также в Drive; GitHub хранит ссылки и небольшие обезличенные отчёты.

## Имена и идентичность
Tool slug описывает операцию: ground-ucx, vpm-grid, npm-window-bake.
Job: <trello-id-lowercase>-<short-action>, например ai-20261002-05-ramp. Сохранять оригинальный ID внутри документа. Если постоянного ID нет, использовать trello-<card-short-id>-<action>, не выдумывать номер карточки.
Case: case-001-ramp, case-002-curved-edge — уникально внутри инструмента.
Ветка: work/<author>/<tool>/<job-id>. Author — согласованный личный slug (roman-kasyan, artem-nagornov); имена для примера, не подтверждённые GitHub-логины.
Версии кода — commit/tag, не final-final-v2.py. Клиентский нейминг выдачи регулируется ТЗ отдельно.

## Постоянство путей
Новый инструмент остаётся в tools/ на всех стадиях. Принятие меняет статус, не путь.
Все имеющиеся разработки перенесены в tools/; [карта переноса](repository-migration.md). Не восстанавливайте прежние каталоги из старой ветки. Переименование сохраняет исходные ID и авторство. Новый перенос — отдельный PR с обновлением ссылок, импортов и доступными проверками.

## Совместимость имён
README.md, AGENTS.md, CLAUDE.md, CONTRIBUTING.md и SKILL.md — стандартные точки входа. Python-модули используют snake_case. Закреплённые исходники сторонних навыков, имена файлов опубликованного аддона и исторических JSON-отчётов сохраняются для воспроизводимости. Новые папки и документы — lowercase kebab-case; новые отчёты следуют тому же правилу. ZIP в dist — небольшая установочная поставка, не клиентские данные.

## Перенесённые инструменты
Код VPM и аддона Compact Cut находится в src/. Standalone-вариант Compact Cut остаётся в standalone/, сборщик — tools/, испытания — tests/. Исторические отчёты остаются reports/, исходные протоколы сохранены. Новые задачи и кейсы добавляйте в jobs/ и cases/ по мере появления; не копируйте старые отчёты ради заполнения шаблона.
